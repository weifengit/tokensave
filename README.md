# dsh-tokensave

**DSH（DeepSeek Harness）多项目工作台插件** —— 在 DSH Web 界面里增加「项目中心」与「工作台」两个 tab：卡片式管理多个代码项目，dockview 多面板工作台把主对话、项目预览、免费模型探索者、共享黑板同屏自由编排；配齐一整套智能体协作的通知与自动化能力（侧边栏呼吸灯/角标、通知面板、提示音、自动继续），并对宿主主对话做大量体验优化；还内置一条「tokensave 探索链路」，把方案探索类任务并行委派给免费模型，为主 agent 省 token。

安装后打开工作台即可使用，无需配置。

## 功能一览

### 项目中心

- 把常用代码目录登记成项目，**卡片 / 列表**两种展示，按名称 / 创建时间 / 更新时间三种排序（偏好持久化）。
- **从 GitHub 克隆项目**：支持公开与私有仓库（走本机 `gh` 登录态，凭据经 URL 限定的环境变量注入，不进 argv、不落盘），实时显示克隆阶段与进度；还提供「我的仓库清单」，列出你 GitHub 账号下的仓库（含私有）按最近推送排序，可搜索、点选即填地址。
- 卡片上直接可见：活跃对话 ①②③ 序号点、「● 已启动」调试标记（dev 服务在跑时出现，点击进工作台并自动并排打开项目预览 + 主对话）。
- 每个项目可开新会话；切项目按「最近对话更新时间」排序，最活跃的排最前。

### 工作台（dockview 多面板布局）

- **三 dockview 实例骨架**：主侧栏 / 编辑区 + 面板区 / 辅助侧栏，面板带标签页，可拖拽重排、跨实例拖动（落点浮层实时预览）、最小化 / 最大化；面板标签在会话运行中显示蓝色脉冲点。
- 可停靠面板：**主对话**（宿主原生输入条停靠在其底部）、**项目预览**（devUrl iframe，可刷新 / 新窗口打开）、**探索者窗口**（每个免费模型一格，可最小化 / 最大化 / 双击全屏）、**共享黑板**、**协作沟通时间轴**、**协作收益**（按真实 usage 折算省下的 token 与费用）。
- **状态栏**：左侧实时提示（进行中小圆点蓝色脉冲、完成变灰不重复文案、出错红字），右侧历史会话切换 / 新建会话 / 保存布局（与默认布局不一致时黄色脏标记）/ 默认布局一键恢复；窄屏自动换行两行。
- 「保存 / 恢复布局」整块存取：面板排布 + 区域收起状态 + 侧栏宽度，按项目各存一份；另有自动快照，刷新 / 热重载后现场原样恢复。
- **探索者设置**：标题行按钮弹出面板，按默认 / 免费 / 收费三区列出可用探索者模型，逐个或整组开关，选择即时持久化。面板位置**与齿轮「设置」面板共用同一个 popPlacement**（`client/src/panel/chrome-position.ts`）：挂在按钮下方 6px、右缘对齐按钮、宽 300、最高 72vh；侧置竖轨时与齿轮面板一样从轨内侧向上长。滚动条内嵌（细、圆头、留透明边），不占外沿。加载**先亮上次成功的本地快照、再后台刷新**，接口挂掉（`Failed to fetch`）时保内容并给「重试」，不再白屏。
- **标题行位置（顶部 / 左侧 / 右侧）**：齿轮里「标题栏 → 位置」三选一。侧置时标题行收成一条 44px 竖轨（图标 + 竖排项目名在上，区域键 / 探索者设置 / 设置齿轮在底部），顶部那一整行的高度还给内容；状态栏仍贴底横满。偏好全局一份（`tokensave:desk-chrome.v1`），窄屏（覆盖式抽屉布局）一律按顶部渲染。

### 侧边栏通知体系

- **呼吸灯**：项目中心入口的小圆点——有对话存活（运行中 / 待确认弹窗 / 上一轮未正常结束）才亮，绿=正常、黄=待处理（黄覆盖绿）；有对话在跑时依次闪烁成跑马灯。结局判定双路：会话停止后约 0.9s 即时重判 + 10s 节流兜底扫描（8s 超时、负结论须新鲜等多重加固）。
- **黄 / 蓝角标**：黄=需处理的对话数（待确认 + 未正常结束），蓝=未读的正常结束数；点击打开同一块**跑马灯通知面板**并钉住（提示音设置 + 自动继续设置 + 对话清单三块），条目直达对应对话工作台，行内「已读」「继续」按钮，已读写 localStorage 不重复提醒；鼠标移向面板的路径有「走廊命中测试」保护，不会走一半消失。
- **提示音引擎**：完成 / 中断两类各自独立音效（2 录音 + 2 合成 + 静音），四种时长模式（一声响 / 一分响 / 一直响 / 自定义分钟随心响）+ 音量调节；起音经专门设计——角标先上屏、声音随后半拍（约两帧），标签页隐藏时 120ms 定时兜底补发，切走的页面不吞音。
- **自动继续引擎**（常驻，不依赖面板打开）：按中断类型决策是否代发「继续」——输出被截断总是自动；瞬时故障（网络 / 超时 / 5xx / 429）自动重试；永久故障（鉴权 / 余额 / 上下文超长）不自动、交人工；待确认 / 用户主动停止不自动。护栏：连续次数上限、冷却退避、用户一介入即取消排队；可重试关键字自定义。

### 主题与外观

- 深 / 浅色主题全局一份，随宿主自动切换；页面刷新后左侧边栏自动保持收起。
- 标题栏位置（顶部 / 左侧窄轨 / 右侧窄轨）、皮肤（底色 + 背景图）、字体（字号档位 + 字族）集中在一个齿轮入口里调。
- **皮肤覆盖整页**：【对话 / 轨迹 / 项目中心 / 工作台】四个 tab 的整页（含顶部标签行）一起变，不再只是 tab 下面那块（见 `client/src/panel/skin-layer.ts`）。
- 停靠的原生输入条与工作台配色一致：外框保留、底色弱化，悬停 / 聚焦不突兀；切回宿主「对话」tab 自动恢复原生样式。

### 主对话体验优化

- **输入框高度调节**：内容有多高自动加高多高（不出内部滚动条，上限可视高-160px）；上沿抓手可手动拖拽固定任意高度（持久化、刷新仍在、内容变少不收回），重置按钮 / 双击抓手交还自动模式。
- **过程折叠**：每轮的工具调用与中间过程折叠为一行「过程 N 步 · 工具 M 次」、上下文注入折叠为一行「上下文注入 ▸」，仅该轮最终回答 Markdown 展开渲染；界面只渲染最近 40 轮。
- **阅读视图三档筛选**：全部 / 只看我发的 / 只看 AI 回复；筛选状态是模块级共享真值——工作台卡片与最大化浮层两个实例任一处切换另一处立即同步，并持久化。
- **任务清单自动收起**：本轮跑完（运行→停止且不在等确认）自动把宿主展开的任务规划面板收起，可再手动展开。
- 贴底跟随 + 上滚闩锁：流式输出时上滚阅读不被打断；切换 tab 再回来滚动位置原样保持。
- 「加载更早」瀑布式回翻：先放大本地轮数窗口、再请宿主拉更早历史，新内容从顶部生长、正在看的内容原地不动。
- 正文宽度把手（往外拖变宽、松手落盘，与宿主偏好键共用）、滚动条滚动时显形停下淡出。

### tokensave 探索链路

任意会话说「请调用 tokensave」即可触发：

1. **场景识别**：按 cwd 里有无项目标记文件与用户措辞，判定「从零新建 / 修改现有代码」。
2. **并行派发**：向多个免费模型探索者（默认预设 3 个，可在探索者设置里改）分别创建会话、下发带侧重点的任务。
3. **共享黑板沉淀**：探索者把坑点 / 方案 / 需求写入插件自建黑板（`board_post` / `board_list` / `board_clear` 三工具，按工作区隔离、TTL 过期）。
4. **交叉验证与评审**：等全员发帖（或超时）后评审汇总，产出一份任务**简报**回主对话，由主 agent 按简报执行文件操作。

省钱口径不是估算：「协作收益」面板直接读各会话 assistant 消息的真实 `usage`，探索者跑在免费模型上、实际支出为 0，按主 agent 单价折算即为节省额。

### 移动端适配（dsh-remote-mobile）

- **响应式窄屏工作台**（断点 900px，与远程插件 mobile presets 一致）：中部永远整宽，左右侧栏变覆盖式抽屉（同时只开一个，三键开关 + 遮罩点击收起）；触屏上把手隐藏、标题行 / 状态栏 / 标签按触屏放大（按钮 ≥ 32px），状态栏换行两行；窄屏默认「一个窗口占满编辑区」——进手机即自动最大化主对话，转回宽屏只还原自动最大化的那个；手机上的抽屉开关不污染桌面端布局配置。
- **跨设备数据同步**：手机端经 dsh-remote-mobile 网关以局域网 / 虚拟网 IP 访问，与桌面端 127.0.0.1 不同 origin、localStorage 互相读不到——项目注册表真相源改为宿主服务端文件落库（`~/.dsh/tokensave/`），所有来源读写同一份，桌面与手机项目列表自动一致（服务端水合 + 广播重渲染，首次拉取延后不与首帧抢资源）。

## 架构

| 路径 | 内容 |
| --- | --- |
| `src/` | 插件服务端（cordis）：`tokensave_delegate` 委派工具、黑板三工具、系统提示词注入、编排 workflow、探索者会话创建、模型路由、场景识别、Web 路由 |
| `src/auto-commit.ts` | 会话轮次结束自动提交（`agent/turn-stopping` → `git add -A && git commit`），配置 `~/.dsh/tokensave/auto-commit.json` |
| `client/src/` | 工作台前端（React）：项目中心、DeskDock 布局、主对话 / 预览 / 探索者 / 黑板 / 时间轴 / 收益各面板、主题皮肤、提示音、滚动记忆 |
| `dist/client.js` | esbuild 打包产物（`__ModuleLoader__` 注册格式，宿主直接加载它）。已被 `.gitignore` 忽略，克隆后需 `pnpm install && pnpm build:client` 生成 |
| `scripts/check-*.mjs` | 自检断言（对源码做文本正则断言，不需要浏览器），`pnpm test` 全量跑 |
| `scripts/build-client.mjs` | 客户端构建脚本 |
| `scripts/release.mjs` | 版本递增 + CHANGELOG 生成 + git tag |
| `docs/MAINTENANCE.md` | 维护约定：铁律、发版档位、commit 规范、接口冻结、排错备忘 |

服务端通过 `cordis.patch.yml` 以组合包（bundle）形式挂载，注册宿主能力：`tools`（4 个工具）、`systemPrompt`（一段委派指引）、Web 路由（`/plugins/dsh-tokensave/board|fs|explorers|scope|project-info|mkdir|explorer-settings|clone|clone-status`）。

插件数据存放在 `~/.dsh/tokensave/`（探索者选择等）；黑板数据由插件自建存储管理。

## 安装

尚未发布到 npm，目前以开发模式安装（要求已安装 dsh CLI，Node ≥ 22）：

```bash
git clone https://github.com/weifengit/tokensave.git
pnpm install                # 在仓库目录内
ln -s /path/to/tokensave ~/.dsh/profiles/web/dsh-tokensave
# 重启 dsh web 后生效（插件源码改动不热重载）
```

或走正式的 profile 安装流程：

```bash
dsh plugin --profile web add /path/to/tokensave
```

## 开发

```bash
pnpm install
pnpm check          # TypeScript 类型检查
pnpm test           # 全量自检（scripts/check-*.mjs）
pnpm build:client   # 重建 dist/client.js，刷新页面生效
```

两条铁律（详见 [docs/MAINTENANCE.md](docs/MAINTENANCE.md)）：

- **改行为必须同步改断言**：`scripts/check-*.mjs` 会把旧写法钉住，只改行为不改断言则 `pnpm test` 必 FAIL。
- **客户端源码改动必须重建**：`pnpm build:client` 后刷新页面；判断「修了没生效」先对 `dist/client.js` 的 mtime。

## 版本与发布

版本号由脚本自动递增，不需要手改 `package.json`：

```bash
pnpm release patch   # 修 bug / 小调整
pnpm release minor   # 新功能 / 用户可见改进
pnpm release major   # 破坏性变更
```

脚本自动：递增版本 → 收集上个 tag 以来的 git 提交按「新增 / 修复 / 改进 / 文档」分组写入 `CHANGELOG.md` → 提交并打 `v<x.y.z>` tag。可加 `--notes "补充说明"` 追加人工备注。

改动提交是**自动**的：插件监听会话轮次结束（`agent/turn-stopping`），只要工作区有改动就在后台
`git add -A && git commit -m "chore(auto): …"`，不再依赖模型记得执行。开关 / 发版模式 / 日志位置
见 [docs/MAINTENANCE.md](docs/MAINTENANCE.md) 的「自动提交」一节（配置文件 `~/.dsh/tokensave/auto-commit.json`）。

## 兼容性说明

- 针对 DSH `0.2.0-rc.2` 系列开发（`@deepseek-ai/dsh-brand` / `dsh-llm` / `dsh-tools` 等依赖同版本）。
- 宿主 DOM 选择器一律使用稳定属性（如 `[data-composer-card]`），不依赖 hash 类名。
- 内置黑板工具与 `dsh-call-session` 插件的同名工具是刻意的兼容设计（参数 / 返回结构对齐）；两者同时启用时以先注册者为准，建议二选一。
